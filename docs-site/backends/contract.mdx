Dogear talks to an **adapter**, a few async functions you implement against whatever you use. Any backend that keeps the rules below works. On Node, [`createDogear`](/backends/server) keeps all of them for you.

## The Comment

```ts
type User = { id: string; name: string; avatar?: string; admin?: boolean; agent?: boolean };

type Comment = {
  id: string;              // any unique string (uuid, Firestore id, serial)
  page: string;            // path + query it was made on: "/settings?tab=security"
  parentId: string | null; // null on a thread's first comment, the root's id on a reply
  body: string;            // 1–2000 chars, trimmed
  author: User;            // set by the backend from the session, never trusted from the browser
  anchor: Anchor | null;   // set on roots only; store it as opaque JSON
  createdAt: number;       // epoch ms
  editedAt: number | null; // epoch ms of the last body change
  resolved: boolean;
  reactions?: Record<string, string[]>; // each emoji to who picked it
  mentions?: { id: string; name: string; handle: string }[]; // who its @handles are, set by the backend
  state?: { key: string; data: unknown }; // roots only: the form on screen when it was written (≤ 64 KB of JSON)
};
```

`Anchor` is opaque to your backend. Store it as JSON, in a `jsonb` column, a map or a string, and return it unchanged.

## The adapter

```ts
import type { Adapter } from "@harshi04/dogear";

const adapter: Adapter = {
  me,       // () => Promise<User | null>          null hides the layer (signed out)
  list,     // (path) => Promise<Comment[]>         every comment whose page's path is `path`, oldest first
  create,   // (NewComment) => Promise<Comment>     NewComment = { page, body, parentId, anchor }
  update,   // (id, { body } | { resolved }) => Promise<Comment>
  remove,   // (id) => Promise<string[]>            every id deleted
  subscribe // optional: (path, onChange) => unsubscribe
  listAll   // optional: () => Promise<Comment[]>    every page, oldest first; what dogear mcp and the tray read
  join      // optional: (name) => Promise<User>     sign a visitor in as a guest
  react     // optional: (id, emoji) => Promise<Comment>  toggle the current user's reaction
  people    // optional: () => Promise<Person[]>     who can be @mentioned: Person = { id, name, handle, avatar? }
};
```

## The rules every backend keeps

<Steps>
  <Step title="The author comes from your session">
    Never trust an author sent by the browser.
  </Step>
  <Step title="Validate on the way in">
    Run `validateNew(input)` from `@harshi04/dogear` on anything the browser sends to `create`. It's safe on a server. Or enforce the same limits in your database rules. `page` starts with `/` and is at most 300 characters, `body` is 1 to 2000 characters after trimming, and a root has an anchor while a reply has none.
  </Step>
  <Step title="Match list by path, ignoring the query">
    `/settings` and `/settings?tab=security` share threads. Store a `path` column, the `page` up to the first `?`, and index it.
  </Step>
  <Step title="Anyone who can see the page can read, reply, resolve and reopen">
    Access to pages is yours to decide. If someone can't open a page, `list` returns nothing for it, or throws.
  </Step>
  <Step title="Only the author edits, and the author or an admin deletes">
    Editing sets `editedAt`. `me()` returns `admin: true` for whoever your backend treats as an admin, and `remove` must check the same thing. The flag only decides which buttons show.
  </Step>
  <Step title="Deleting a thread's first comment deletes its replies">
    `remove` returns every id that went.
  </Step>
  <Step title="Throw on failure">
    The layer rolls back its optimistic change and shows a toast.
  </Step>
</Steps>

## The REST shape

If you'd rather write a server route than an adapter, implement these and use `httpAdapter("/api/comments")`. Cookies are sent with every request.

| Method | Path | Body | Returns |
| --- | --- | --- | --- |
| `GET` | `/api/comments/me` | | `User`, or 401 when signed out |
| `POST` | `/api/comments/me` | `{ name, tint? }` | `User`, signed in as a guest. Optional, for `httpAdapter(…, { guests: true })` |
| `GET` | `/api/comments?path=/x` | | `Comment[]` |
| `GET` | `/api/comments?all=1` | | `Comment[]` for every page, without `state`. Optional, for `dogear mcp` and the tray |
| `POST` | `/api/comments` | `NewComment` | `Comment` (201) |
| `PATCH` | `/api/comments/:id` | `{ body }` or `{ resolved }` | `Comment` |
| `DELETE` | `/api/comments/:id` | | `{ deleted: string[] }` |
| `GET` | `/api/comments/mentions` | | `Comment[]` where the current user is @mentioned, on pages they can open, newest first, without `state`. Optional, for mention alerts |
| `GET` | `/api/comments/people` | | `Person[]`, who can be @mentioned. Optional, and anything but 200 means nobody |
| `POST` | `/api/comments/:id/reactions` | `{ emoji }` | `Comment`, with the current user's reaction toggled. Optional |

For reactions, `toggleReaction` and `cleanReaction` check for exactly one emoji that isn't one of the rude few, and `roomForReaction` allows at most `MAX_REACTIONS` kinds, else answer 422 with `{ error }`.

### Errors and outages

- **Any non-2xx is a failure.**
- **A 422 means the route refused the text itself,** such as a moderation check on a comment, an edit or a guest's name. Answer `{ "error": "…" }` and the layer shows that line to the writer, keeping what they wrote so they can change it.
- **When your backend is down, answer 503,** or anything but 401 or 403 on `/me`. The layer hides after two failed looks in a row, or at once if it never loaded. It looks again after 30 seconds, then 1 and 2 minutes, and comes back when you do.
- **Requests time out after 8 seconds.** Change it with `httpAdapter(…, { timeout })`.
- **Nothing the backend sends can break the host page.** Rows that can't be drawn are dropped, and a render error removes only the layer.

## Guests

On a public page, such as a portfolio or docs, visitors have no account. With `join`, the layer shows them the threads read-only and asks for a name the first time they write.

- **Your backend mints the guest.** `POST /me { name }` creates a random id, keeps it in the session in an httpOnly cookie, signed or server-side, and returns the `User`. Never accept an id from the browser.
- **Names are 1 to 40 characters** after trimming. `cleanName` from `@harshi04/dogear` does it.
- **`tint` is the avatar they picked,** when the page offers some through `avatars`. It's a key, not a colour. Keep it on the user and their comments only if it's one of your page's keys, and `cleanTint` checks its shape. Drop anything else, and the layer picks one by id.
- **Public pages need limits.** Rate-limit `create` and `POST /me` per guest and per IP. Consider letting only a thread's author or an admin resolve it, pass `resolvers="authors"` so the button agrees, and keep an admin who can delete.

## Agent tokens

`dogear mcp` lets a coding agent read threads, reply and resolve. Against a REST backend it runs `httpAdapter(endpoint, { token })`, which sends `Authorization: Bearer <token>` instead of a cookie. Accept that token in your route and sign the request in as an agent user.

```ts
if (bearer(request) === process.env.DOGEAR_AGENT_TOKEN) return { id: "agent", name: "Agent", agent: true };
```

- Compare tokens in constant time, keep the token out of the browser, and rotate it like any key.
- `agent: true` puts an **Agent** badge on its comments. The usual rules still apply. It can edit only its own comments, and it isn't an admin unless you say so.
- Return every page from `GET ?all=1`, the adapter's `listAll`, so the agent can see all open feedback at once.

`createDogear({ agentToken })` does all of this for you.

## Live updates

Without `subscribe`, the layer polls `list` every 3 seconds while comment mode is on and the tab is visible. That's plenty for a review with a handful of people.

If your backend pushes changes, as Supabase Realtime, Firestore `onSnapshot`, Convex, Liveblocks or Pusher do, implement `subscribe` and call `onChange()` whenever a comment on that path changes. The layer then fetches again.
