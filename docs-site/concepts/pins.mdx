## Picking the element

In comment mode, the element a press would land on is outlined as you move, with a label such as `button "Start free trial"`. That's the element the comment is anchored to. Dogear takes it when you release, so scrolling while you write doesn't move it.

## What a pin remembers

A pin is stored relative to its element, using a selector and a fingerprint.

- **A selector.** It starts at the nearest stable `id` or unique `data-testid` (also `data-test`, `data-qa` or `data-cy`). Below that it's structural, such as `div:nth-of-type(2)`, and it reaches into open shadow roots.
- **A fingerprint.** The element's first 60 characters of text.

It also keeps a viewport position as a fallback, and a short label for the thread card.

<Tip>
  Add test ids to the elements people comment on. Pins then survive changes to the page above them.
</Tip>

## Naming an element yourself

Put `data-comment-label` on an element to choose the label its threads show.

```html
<section data-comment-label="Pricing table">…</section>
```

## When the page changes

- **Pins follow their element** through scrolling, including inner scroll containers, and resizing.
- **If the element is gone,** the pin is drawn faded at its fallback position.
- **If the element's text changed** since the comment was left, the pin gets an amber dot, so you can spot comments that may already be fixed.
- **Across tabs of a page,** such as `?tab=billing`, a pin made on one tab only shows on another if its element is there, with matching text.

## Pages and threads

Threads are keyed by path without the query string, so `/settings` and `/settings?tab=billing` share them.
